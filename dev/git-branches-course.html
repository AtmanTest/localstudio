📚 Cours Git — Comprendre les Branches (Niveau Débutant)

1. Qu'est-ce qu'une branche ?

Objectif : Visualiser une branche comme un chemin dans le temps.

ConceptDescription
Branche (Branch)Une ligne de développement parallèle. Chaque branche est un historique complet de commits.
Main/HEADLa "réalité" du projet — ce que les utilisateurs voient.
ForkVotre copie personnelle d'un repo (pour expérimenter sans risque).

💡 Analogie : Une branche = une route de construction. Main = la route principale.

2. Pourquoi utiliser des branches ?

UsageDescription
Dev en parallèleTravailler sur plusieurs features sans bloquer main.
RevisionsGarantir que des versions stables existent toujours.
IsolationTester une feature risquée sans toucher à main.

💡 Règle d'or : "Never touch main directly"

3. Cycle de vie typique (Workflow)

ÉtapeAction GitRésultat
Créergit branch devNouvelle branche vide.
Travaillergit commit -m "feat"Commits dans dev.
Pushergit push origin devDev sur GitHub.
Pull RequestGitHub UI ou CLIMerge vers main.

💡 Workflow moderne : Feature branches + Pull Requests

4. Commandes Git essentielles

CommandeDescription
git branch -aLister toutes les branches (local + remote).
git push origin <branch>Pusher une branche sur GitHub.
git pull requestOuvrir un PR vers main (GitHub CLI).

💡 Méthode ISTQB : "You can't manage what you don't measure"

5. Bonnes pratiques

RègleDescription
NamingClair et descriptif : feature-login, bugfix-42.
Small commitsUn commit = une idée. Facilité de merge.
PR ReviewN'importe jamais pusher directement sur main.

💡 Méthode ISTQB : "Configuration Management = Version Control"
